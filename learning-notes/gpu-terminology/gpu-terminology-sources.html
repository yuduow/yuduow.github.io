Notes

Same Role, Different Unit

An SM, CU, Google TensorCore and NeuronCore have different sizes and capabilities. Google TensorCore names a compute block; NVIDIA Tensor Core names a matrix engine.

Scratchpads Have Different Scopes

CUDA shared memory and AMD LDS support thread cooperation. TPU VMEM and Trainium SBUF serve tile programs and engines. These are role comparisons, not interchangeable memory models.

Precision Has Three Parts

Distinguish operand storage, multiply precision and accumulation. FP32 output does not guarantee full FP32 multiplication. Format support and throughput vary by instruction and generation.

  • Hardware examples are explicitly bounded to Hopper, CDNA 3, TPU v6e and Trainium2; this is not a claim about every NVIDIA, AMD, Google or AWS chip.
  • CUDA and HIP use a thread hierarchy. Pallas TPU and NKI express tile/tensor programs. A Pallas grid is generally sequential on a core; an NKI program_id is an SPMD instance coordinate, not a thread ID.
  • Pallas and NKI entries are software interfaces to hardware concepts, identified in column subtitles. Pallas TPU is experimental; these APIs can evolve. The matrix-format row describes hardware examples, not a promise that every type is accepted by every kernel API.
  • Precision rows show selected matrix modes, not all supported storage types or instructions. TF32 is reduced-precision multiplication; FP8 variants are not automatically numerically interchangeable.
